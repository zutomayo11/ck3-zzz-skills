# Blender 与 CK3 验证

Blender 只验证几何、动作、挂接、相机和离线构图，不代替 CK3 的 GUI 求值、加载覆盖、节点分支或最终显示。先检测 `E:\Blender\blender.exe` 和 `E:\Blender\blender-launcher.exe` 的真实版本，再选择当前设备支持的 GPU 后端；记录实际渲染引擎、设备和后端，CPU 回退要明确。

对照至少使用：真实 CK3 原版几何白模、用户确认正常的旧目标角色、当前待修版本、候选版本，必要时再加材质预览。白模必须是实际网格的简化材质，代理体只能标为代理。统一相机用途、动作语义、采样时点、分辨率、宽高比和控件可见区域，但不强行统一身高。

每个候选检查头顶/眼线/肩腰范围、居中/俯仰/朝向、裁切、道具、穿出、动态漂移和循环；至少检查开始、中段、极值和循环衔接。输出完整纹理和模拟控件裁剪图；UI 缩放、遮罩、父级锚点、镜像和宽高比单独记录。图像生成后实际打开检查。

CK3 实机证据要记录实际入口、角色/皮肤、版本/哈希、启用顺序、返回相机键/ID、动作、节点、截图和观察结果。离线通过不升级为实机通过。没有稳定入口、授权或可复现截图时记 `NOT_TESTED`/`BLOCKED`，不改存档、播放集或正在运行游戏取证。

用户明确表示已在 CK3 观察到恢复时，记录为用户实机反馈，并限定在其描述的范围；缺逐入口截图或调用链时，不把它扩写为全入口通过。用户暂缓 Blender 图审时标为 `DEFERRED_BY_USER`；前台脚本中断前的部分渲染图只能作为诊断中间产物，不能冒充已完成的白模或前端窗口对照。即使完整离线图审通过，也不能替代 CK3 实际取点与 GUI 裁剪。

报告分开计算定义完整率、静态接入率、离线构图通过率和实机覆盖率，写清分母。可复用旧证据的前提是输入和依赖未变，并标注原始轮次；资源、GUI、路由或节点改变后，旧图不再证明新组合，只能保留为注明来源的历史组件证据。

## 可复用的渲染与预览检查

- **网格与贴图来源**：核对可见几何与成品 mesh，材质读取候选实际 DDS/shader palette，不用工程源贴图或近似皮肤冒充成品材质。白模是同一实际网格换中性材质，原版对照也读取实际原版网格和动画。
- **材质槽**：白模/材质切换逐槽替换，保留面片的 `material_index`；清空槽会丢失索引，之后重加材质不能自动恢复。切换前后检查槽数和面片索引，并实际看眼睛、头发、服装等分区。
- **透明控件模拟**：用透明背景输出（Cycles `film_transparent=True`），检查 alpha 不是整幅不透明。按实际 GUI 顺序处理肖像镜像及 widget-space body mask 的 alpha，不把遮罩 RGB 当 alpha；记录原遮罩哈希、控件尺寸和过滤差异。完整纹理与模拟控件分开保留，不称为 CK3 截图。
- **采样与图审**：中段从实际总帧数计算，不沿用其他动作的帧号；极值来自本角色实际头部运动。所有皮肤在首/中/极值/末帧形成白模和材质汇总图，逐张打开。保留失败中间产物，但不要混入最终 PASS 的收据和图集。
- **Blender GUI 预览**：保存含可编辑场景和打包图像的 `.blend`。设置图像编辑器时限定 `bpy.context.screen` 的当前区域；Blender 5.2.1 中未激活工作区的 `area.type` 转换会延后，`area.spaces.active` 仍可能是 `SpaceView3D`，不能立即赋 `.image`。后台回读验证打包图像、当前编辑器与对象后再打开前台；只启动进程不等于预览成功。
