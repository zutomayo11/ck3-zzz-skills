# 反例与回归表

当前排错以[独立3D前置／正式模型Pack 规范](../../ck3-zzz-3d-mod/references/zzz-core-pack4-workflow.md)为准。已有正确调用、节点和数值保持；历史案例只支持其绑定版本。

| 症状 | 检查点 | 危险做法 | 正确验证 |
|---|---|---|---|
| 改default后仍播放原版姿势 | GUI类别、自动权重、手选标志 | 把回退值当强制选择 | 解析实际有序权重与资源；保留特殊分支和旧手选 |
| 小头像或地图标记不同步 | 各控件实际API和动作参数 | 全部改animated或只改共享头像 | 保持GetPortrait；地图独立接入展示选择器 |
| 马入镜但人物悬空 | 同动作人体/坐骑世界变换、实际支撑几何 | 继续调相机或套骨盆差 | 骑乘固定区域最低5%与战车脚底校准，保持地面附件 |
| 已有引用全有效但附件仍漏 | 原版预期modifier/gene/template/accessory/entity链 | 只检查存在的引用 | 比较应有附件全集及文化/装备/外观条件 |
| 死亡动画存在但主面板待机 | GUI API/类别到状态闭包 | 只改dead实体或用手选死亡代替真正死者测试 | EvenIfDead/dead入口与活人/普通回退分别验证 |
| 死者换装反复变量报错 | 死亡作用域、自动外观条件 | 同层加is_alive假定短路或猜旧变量 | 真条件分支隔离；保留未修状态，不编辑存档 |
| 开debug无标签 | 控件存在、根可见条件和队列人物 | 认定InDebugMode失效 | 查被删除控件；REQUEST与引擎状态分开 |
| 内阁与理发店动作不同 | 原版任务顺序、文化图形及循环 | 按Pack判异常或统一欧洲姿势 | 同文化原版对照与任务切换，保留原选择 |
| 相机文件存在但 GUI 没调用 | 控件、slot、路由和覆盖顺序 | 只看定义数 | 静态调用链 + 实机入口 |
| 路由存在但返回错误/不存在 ID | 本地化值、语言、定义名 | 只看键名 | 展开返回值并查定义 |
| 同名原版相机被覆盖 | 加载顺序、最终来源 | 批量改名/删名 | 隔离加载和来源记录 |
| 只修载入后 HUD/事件坏 | 正常基线和共享依赖 | 连续叠补丁 | 单变量候选 + 回归矩阵 |
| 把全部 Custom 改回原版后称为“历史遗漏” | 修改前后逐入口路由、基线和版本证据 | 按名称批量恢复或把旧相机归零 | 对比首个异常候选，只处理有差异且能解释该入口故障的最小变更 |
| 旧接口前缀看起来过时 | 当前 API 和调用者 | 批量清理旧名 | 证明无调用后再处理 |
| body/shoulders/event_center 被等同 | 用途、节点、姿态语义 | 复制一个相机全局替换 | 同用途对照图和运行证据 |
| environment 与 camera 混用 | 参数类型和位置 | 交换字段 | 解析完整控件并实测 |
| 角色作用域与 slot 不一致 | 实际显示角色 | 从 center 名字猜角色 | 按 slot 追作用域 |
| 静态 Custom 括号/参数错 | 完整表达式、参数数量 | 强行改 animated | 文本解析 + 控件截图 |
| 活动普通人物误入私有center | 实际人物身份、getter调用者及定向取景条件 | 忽略普通分支或重建旧别名 | 接入center/有限例外与普通typed getter分开验证，两队列回归 |
| 前端异常导致共享根改坏其他入口 | 根节点依赖图 | 批量改公共根 | 专用叶节点候选 + 全依赖回归 |
| 游戏内正常但载入拍到模型表面 | SaveGameItem 接口、专用相机与有效画像组 | 编造人物接口或改公共相机 | 专用 default 私有节点、human/anime 原节点；未知组阻塞，普通人物对照 |
| 正式载入卡人物区域完全空白、test 同一卡片可见 | 同一存档的实际加载组合、GUI 纹理请求、正式 portrait group/gene、相机分支和新日志 | 把启动期 gene/节点报错直接定为根因，或继续调相机距离 | 先区分纹理是否生成；保留 test/正式截图、候选哈希与新日志，逐层对照 `GUI -> portrait group -> camera branch -> carrier node` |
| 世界坐标逐帧零误差但头像/内阁/事件仍错位 | `idle`、`idle_entry`、`zzz_camera015_*` 的可达状态、重复序号、`next_state`、正式 body clip 与 carrier clip | 只比相机/节点坐标，或缺状态时固定回 `idle` | 将 test 状态图作为语义 donor；逐状态按名称和重复序号严格匹配正式身体动作，验证闭包、clip、帧率、骨序与道具挂点；缺匹配即候选失败，并保留 CK3 实机矩阵 |
| 活动白模正常但骑乘/结束队列异常 | 当前请求类别、实际分支、两个队列、定位及UI裁剪 | 引用旧别名方案或把离线白模当实机 | 按现行center/定向取景结构与普通getter逐入口验证 |
| 节点存在但引擎未取用 | 运行时图像和加载日志 | 把 Blender 手工选点当事实 | CK3 真实入口验证 |
| 旧日志被当新结果 | 版本、哈希、候选路径 | 复制旧结论 | 新候选证据和来源 |
| 完整纹理正常但 HUD 裁头 | 父级裁剪、遮罩、scale、锚点 | 只调相机 | 纹理图 + 控件可见区图 |
| 只看静置帧 | 动作和辅助同步 | 用一个 idle 代表全部 | 首/中/极值/循环 |
| 本来侧身/背向被当错 | 事件动作和 camera 语义 | 一律校正正面 | 保留剧情姿态并核对定义 |
| 原版儿童误入 3D 分支 | portrait type、年龄资源、路由条件 | 改 DNA/性别回避 | 原版回退和儿童样例 |
| 只保护 mesh/anim/dds | GUI、相机文本、asset 引用 | 只做资源哈希 | 运行链和引用哈希 |
| 用旧载入图证明新版事件/HUD | 入口和候选哈希 | 跨入口复用截图 | 每入口新证据 |
| 定义/路由/文件/渲染数很高 | 正确分母和画面 | 合成“全部通过” | 四类覆盖率分开 |
| 检查器通过但没有对应画面 | 检查范围 | 把静态 PASS 当实机 PASS | 对应入口截图 |
| 改版本号冒充回退 | receipt、文件内容、加载顺序 | 只改版本字段 | 精确恢复 + 依赖验证 |
| 把增量候选当完整包回退 | 原始完整基线、增量范围、目标收据 | 清空旧文件后用较新备份补洞，形成混版 | 按目标运行路径逐项哈希比对，并清除较新残留 |
| 缺失 GUI 文本只能从历史变换重放 | 来源版本、转换规则、换行符和 BOM | 仅凭语义相同或文件名相同补齐 | 重放后核对收据中的字节级 SHA-256 |

发生回退时，撤销导致回退的最小变更并记录被否定假设；不要在错误候选上继续叠补丁。共享节点、模板、GUI 或生成器改变后，扩大回归范围。

## 载入单入口合入

适用于“用户确认游戏内正常，只修载入”以及从正常版本合入历史局部修复。先核对恢复包完整性；不要在较新故障包上补接 `Custom` 或统一前缀来冒充正常基线。

1. **冻结契约**：记录完整 GUI、路由、本地化返回值、相机定义、节点所属载体、骨序、挂接、旧动画轨道及控件补偿。相机名称/距离没变，不代表实际选中的参考点或最终画面没变。
2. **核对 donor**：检查候选收据、资源和旧截图哈希、原始测试入口，以及资源接线能否适配当前基线。历史载入截图只支持该组件的来源，不证明新组合或其他入口已通过。
3. **局部合入**：只替换载入定义和必要的隐藏资源引用；大厅、书签、游戏内 GUI、公共默认节点及路由名不随同迁移。确需保留已验证隐藏二进制的完整新增叶集时，说明未使用叶无新增调用并核对依赖；不要为了缩小文件数重造骨架后继续沿用旧证据。
4. **结构与坐标回归**：核对旧骨名称/索引/父级/绑定及旧轨道精确保留、状态闭包和道具挂点；对已正常的受影响角色/镜头使用真实身体与配对辅助动画，逐帧比较世界位置/目标。报告动作、帧范围与差值，不用零差值代表所有动作或引擎运行正常。
5. **同版本验收**：生成实际网格白模、材质及控件模拟图；允许实机时，同时检查新修载入和原正常游戏内入口。未实机保持 `NOT_TESTED`；只做局部反馈时保留其原话与范围。

正常角色（例如本项目莱卡恩）可作为同用途的姿态、可见范围和 GUI 对照，但不能把其距离、高度或节点偏移原样覆盖其他角色。保留真实身高和角色专属参数；没有旧 CK3 图时，旧 Blender 理论节点图必须标为“理论几何”，不能写作旧游戏正常画面。

## 空白载入的隔离对照

正式载入区域空白且可用 test 对照时，先不修改正式包。固定同一存档、入口、游戏版本和上游加载组合，保存 test、正式基线、正式候选的包哈希、启用顺序、新日志和截图。按以下顺序缩小问题：

1. test 与正式是否确实加载各自预期包，且没有互斥模型、旧 GUI 或启动器缓存混入。
2. GUI 是否请求同一类肖像纹理；原版人物在该控件是否回退可见。
3. 正式 portrait group/type 与 candidate 相机 selector 是否命中；缺 gene 日志是否在可见 test 中也出现，或有直接的纹理生成失败证据。
4. 已确认生成纹理后，才比较正式组和 test 组的载入专用 position/look-at 节点、carrier、绑定与动画；候选仅改有证据的载入专用定义/GUI；当前自动分流规则见共用规范。
5. 候选能在 CK3 显示后，再回归此前正常的游戏内入口；未覆盖角色、皮肤或入口继续标为 `NOT_TESTED`。
