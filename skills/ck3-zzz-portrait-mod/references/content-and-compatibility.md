# 数据、生成器和兼容

## 真实数据入口

`settings.json.source` 指向素材，`reference` 指向 `D:/CK3-mod/CK3原版参考`。`全角色配置总览.json` 的 `角色模板` 提供每项 `文件`、`读取位置`、`同一角色身份ID`；按指定 JSON 子对象读取 `角色ID` 等配置。不要假设所有角色 JSON 顶层结构一致。

同目录 `角色展示/*.png` 为皮肤立绘。`build_mod.py.load_data` 根据实际文件排序，并优先指定星见雅 `09_烈露濯霜.png`、艾莲 `09_剪刀手艾鲨鲨.png`。更新时先比较旧 `build_manifest.json` 的 index，避免旧档同一个 `zzz_skin` 指到另一张图。

当前生成器含64模板/62身份的明确断言。新增角色需同步总览、数据、计数断言和测试预期，不能只改数字绕过缺数据。多形态可能共享同一人物身份（如安比、比利）；判重使用身份ID，立绘分支使用角色trait。稳定已有 dynasty/house/trait/角色ID；改显示名不改存档标识。

`CK3配置` 包含基础属性、家族、特质等设计；具体键从现有被引用档案和生成代码读取。稀有度、官方介绍、角色语气参考与 CK3 改编数值区分记录，缺失来源不虚构。日常构建不运行 `research_introductions.py`；用户要求补资料时再单独研究并保存来源。

## 姓名与卑微出身

家族分配以已核对的 `CK3配置.家族.原作姓氏` 为依据。用户明确指定的姓名拆分或暂用化名姓氏优先，先同步该字段、姓名字段和家族显示名，并记录其依据及暂用性质。空值或 null 表示未确认姓氏，新召唤使用 `dynasty = none`（Lowborn／卑微出身），不得回退到旧 `角色真名.姓氏`、代号、化名或改编家族显示名。先核对档案中的确认资料及说明，再同步冲突的姓名字段；不要因为姓名含“·”或前缀就推定姓氏。

- 用户确认莱卡恩姓“冯”、名“莱卡恩”；简·杜本名未知，用户指定暂按化名姓“杜”、名“简”处理，两者保留原家族ID，家族显示名分别为冯、杜。芙罗拉姓氏未知，使用卑微出身，“席德”是人物称号。
- 可琳名字为“可琳”，确认姓氏为“威克斯”，注意旧顶层字段曾写反。零号安比顶层姓氏虽空，家族资料明确德玛拉，与安比共享人物身份，保留该配置。
- 人物姓名本地化使用“名字·中间名”，家族另显示姓氏，避免重复。洛克茜中间名“伊芙莉塔”，露西亚娜中间名“德”；不要将中间名吞掉或另建家族。

人物称号使用 `CK3配置.人物称号` 的 `id`、`显示名`，生成 `common/nicknames` 定义和姓名本地化，并在 `after_creation` 使用 `give_nickname`，不把称号拼入名字、姓氏或新增称号特质。席德为 `nick_zzz_seed`；旧档通过一次性迁移仅给无称号的芙罗拉补上（原版触发器 `has_any_nickname = no`），保留已有其他称号。原有代理人身份特质保留。

从 `load_data()` 实际加载的全部模板检查，不仅检查某次手写无姓名单；核对生成的模板家族引用和姓名本地化，再运行 `validate_mod.py` 的姓名及 Lowborn 回归检查。保留旧王朝、家族、人物、身份和皮肤ID；当前只修新召唤家族，不自动清除旧档已有家族，不覆盖玩家自定义名字。新增无姓或带中间名角色时同步扩展回归用例。

## 纸片肖像技术

`build_mod.py` 使用二向箔核心库的 `hm_prophet.mesh` 作为平面载体。PNG 转 RGBA、保持比例并留透明边，当前输出1024×1024 DXT5 DDS；不要用不透明底色填平。attach 到 `bn_h_head_mid`，portrait_group 为 anime；mesh shader 使用核心库的 `portrait_attachment_alpha_to_coverage` 和 `gfx/hmportrait.shader`。

每255项分一个 accessory gene 组；index 从1开始，不能超出范围。皮肤条件依赖 `zzz_skin`，默认/越界回原皮；`normal_portrait_blocked_trigger` 必须保留。生成 `zzz.asset`、accessories、genes、portrait_modifiers 及本地化引用须一致。

纸片平面和原版人体消隐是两条资源链。当前透明载体、黑模型排查及证据边界见 [纸片人消隐与调频](paper-rendering-and-tuning.md#纸片人前面的黑模型)；不要用3D镜头或骨架修改补纸片人材质问题。

## 游戏行为约束

- 调频、收费、结果窗口在 `tuning_ui.py`；角色生成和接口在 `build_mod.py`。世界已有同身份活人时转余波，十连每次创建后更新登记，不能同批生成分身；死亡后可重新召唤。
- 当前单抽100金币、十连1000、自选100余波，成功获取后共享1825天冷却；以 settings 为准。取消自选不扣资源、不占冷却，首次机会/余波/有效冷却继承给玩家继承人。
- 扣钱用原游戏已验证的 `remove_short_term_gold`；不要恢复负值 `add_gold`。日期格式化前将剩余天数转整数。
- 新角色当前从16岁生成并自然成长，这是 Mod 设计，不是原作年龄；不重置现有人物年龄。
- `agent_extensions.py` 在新人物 after_creation 生成两条设定记忆并标记一次性变量；记忆被清理后不在打开调频时补写，旧记忆保留。
- 专武源在 `角色专属武器/*/*_宝物.json`，配套词条和绑定 JSON。宝物ID三处一致、持有者与受益身份精确匹配；世界终身创建一次，销毁不重造，主武器槽为空才自动装备。转赠不授予专属收益。库存图标不等于三维武器模型。

音擎是另一类日志宝物，不套主武器槽或人物肖像。代理人特性、音擎装备条件、独立结果图片、混合池及十连保底见 [纸片人消隐与调频](paper-rendering-and-tuning.md)。
