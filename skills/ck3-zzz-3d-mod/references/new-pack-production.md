# 新 Pack 生产与 Token / 上下文节约

## 适用范围与旧包边界

这是用户指定的生产约定。新绝区零 Pack 采用[角色包内置 ZZZ Core／正式模型包 工作线](zzz-core-pack4-workflow.md)，复用成熟算法。此前成品按各自现装清单保护，无须因新包重新全面审查；已有实现不等于所有游戏入口已验收。相同代码路径没有实际异常时直接复用，不重新研究模型转换、重定向、动作、材质、菜单、资源组织和打包。

新增包通常只更换角色、模型、贴图、原生动画和配置。仅新增角色接受提取/转换、本人 `Galgame_Idle` 菜单默认待机、CK3 动作/眨眼、道具武器骑乘、菜单镜头、宫廷/王座、脚底基准、DDS 与最终包装处理。实际游戏状态沿用当前 CK3 重定向规则。旧包对应成品及已验证结论默认保留。

用户明确要求修改旧包，或当前异常直接指向旧包/共享依赖时，才进入有证据的局部修复。新增角色必需的共享入口、同内容文件及版本元数据允许做必要同步，并说明实际变化；不能借此顺带重建旧模型、烘焙旧动作、重算旧脚底或修理无关历史问题。若入口只能全量操作，先定位其目标筛选和可复用阶段，采用作用于当前包的最小入口；没有实际参数证据，不编造新 CLI。

## 十五条生产原则

### 1. 优先复用现成实现

- 直接沿用既有模板、脚本、目录结构、配置格式和处理流程，只填本包新增输入。
- 不重新推导 Pack1–3 已解决的问题，不为“确认一下”完整分析已验证代码。
- 模板结构与角色资源分开：创建 Test 或迁到新阵营时，按 [Pack 模板迁移与修复经验](pack-template-adaptation.md) 预检隐藏状态/重复变体、道具 T/Q/S、画像组提供者和有效覆盖。复用实现不表示新角色自动满足 donor 的数据契约；当前隐藏 36 槽基础布局及角色特有扩展按 ZZZ Core 契约建立并从成品解码验证，不能套用旧包不同骨序；历史计数不作永久常量。

### 2. 不读取完整历史或巨大记录

- 以当前项目、本包 manifest、最近交接摘要和短状态为准。
- 只有当前报错明确需要时才检索历史关键词和少量上下文；不加载超长对话、旧日志或旧全量构建记录。

### 3. 项目规范只读必要部分

- `AGENTS.md`、README、技能和开发规范原则上完整读一次，后续复用简短规则摘要。
- 单项规则只定位相关章节；新用户指令或相关文件确有变化时才更新摘要。

### 4. 代码按需读取

- 已知文件和符号直接定位，用 `rg` 搜索后只读目标函数、配置段及必要上下文。
- 不无目的地读取大型源码，已确认正常的模块不重复读取。

### 5. 长构建前一次性静态预检

在 Blender 转换、烘焙、导出或完整打包前，覆盖当前包全部角色与外观：

- 全部角色已在正确清单，`group`、family 和 PACK 路由完整。
- 普通角色、特殊骨架、构造体、夏日/换装等分支已覆盖；身份 trait、皮肤编号、accessory 和私有基因模板对应。
- 模型、贴图、原生/默认待机、动画库及配置输入路径存在，必要来源字段可被生成器识别。
- 输出目录、资源前缀、名称、最终 PACK 归属正确。
- 生成器能识别全部新增角色，长任务入口确实只作用于当前包。

先解决清单/路由/路径问题再计算，避免完成烘焙后因简单字段遗漏重来。已有成熟处理逻辑不需要重新源码审查。

### 6. 只验证此次影响范围

- 小改动运行对应测试，不默认跑全项目或所有旧包测试。
- 武器显隐只查对应 shader/mesh 标记和帧区间、显隐测试、必要前后预览、最终引用及必要哈希。
- 菜单命名/布局只查名称、本人片段路由、实际成品列表控件与引用；不跑模型转换、眨眼烘焙或宫廷脚底。
- 共享接口确有变化时检查受影响的单包及组合兼容；没有共享变化时不重复全组合检查。
- 旧版本、旧合并目录或无关历史失败只简短记录，不扩大本包任务。

### 7. 控制命令与日志输出

- 默认安静模式，将完整计算日志留在本地文件，不送入上下文。
- 成功只输出 `命令 + 返回码 + 关键统计 + 输出路径`。
- 失败先提取 `ERROR / WARNING / Traceback / failed assertion` 附近必要行，无法解释时才逐步扩读。
- 不反复读取同份长日志；能用10行解释就不读1000行。

### 8. 图片检查按目的进行

- 仅在需要视觉证据时检查原生姿态、脸/眨眼、菜单镜头、明确视觉修改的前后对比。
- 不为形式验收批量截图，不在后续步骤反复查看已确认正常项。
- 预览使用成品 mesh/asset/shader 的实际引用，离线图不能冒充 CK3 实机结果。

### 9. 长计算不高频轮询

- 在合理进度节点检查进程、错误和预期输出；不频繁回读完整终端。
- 状态未变化时不重复分析或汇报“仍在运行”。必要沟通保持简短，不以持续计算为理由重新规划。

### 10. 一次判断后连续执行

有充分信息后连续完成：`预检 → 转换/构建 → 针对性验证 → 打包 → 最终摘要`。只有真实异常才切入排错，不每个小步骤都重述项目和重新计划。

用户明确说“基本没问题，直接打包”时，停止新增实验、细节完善和额外全量验证，完成当前交付的必要清单、版本及压缩完整性检查。保留当前已知问题的简短说明；不得把停止排查解释成问题已解决，也不继续未经请求的修复。仅更新 skill 时不重建 Mod、不升 Mod 版本。

### 11. 错误按最小范围排查

顺序：`当前报错 → 直接相关文件 → 直接依赖 → 最近修改`。当前层无法解释时才扩大。不要从全项目扫描、全量测试、所有历史日志、所有旧 Pack 或整套流水线研究开始。

每个试验只记录假设、改动范围、观察和结论；同一假设已被否定，没有新证据不换个名称重复。保留最后可用候选及可回退边界，避免同时改变骨架、动画、镜头与全局加载后无法归因。

### 12. 已验证结论默认可信

使用 Pack1–3 成功过的相同代码路径时默认沿用；之后已完成包同理。只有实际异常证据才重新调查，不能用“可能还有问题”启动全面审计。来源或代码确实改变时，仅验证受影响部分。

### 13. 避免重复说明

过程更新只说新增发现、真实异常或下一步要解决的问题。不反复复述已完成事项、包结构、技术原理、Blender 耗时或 Token 消耗原因。

### 14. 维护一份极短状态

优先从当前包独立配置的 current_delivery 定位最近收据与短状态；本轮总入口为 reports/role_core_100/delivery.md，不把历史 pack4_status.json 默认视为现装状态。续接先读本包状态，不重读全过程。只维护一份当前摘要，详细计算日志不混入其中：

```yaml
PACK: PACKN
状态: building / testing / done
已完成: A、B、C
当前步骤: X
未完成: Y、Z
当前异常: 无 / 一句话描述
输出路径: ...
```

### 15. 最终汇报简洁

只报告当前包是否成功、角色、关键验证、注意事项、成品路径，以及相比既有流程是否出现新特殊处理。注明实际验证边界；没有异常不写长篇制作过程。

## 默认决策与优先级

- 没有异常证据，不扩大调查。
- 没有代码变化，不重新审查成熟代码。
- 没有涉及模块，不测试该模块。
- 能复制模板完成，不重新设计。
- 工具只返回有信息增量的结果摘要。

**正确完成当前 PACK ＞ 针对性验证 ＞ 最小必要排错 ＞ 全局检查。** 不为“绝对全面检查”主动扩大范围；节约上下文不能成为省略本包必要处理或隐瞒失败的理由。
