# 事件、活动与队列路由验证

制作规则以[角色包内置 绝区零绝区私有相机／正式模型包 工作规范](zzz-core-pack4-workflow.md#相机调用结构)为准。事件、活动允许并要求对已接入人物使用经验证的私有分流；不要运行历史 Recovery 收尾撤销现有正确调用。

## 调用点清查

从实际有效源码解析文件、事件/活动 ID、人物位和作用域、动作选择树、默认/显式相机、优先级及最终文件来源。无 `camera =` 仍追踪窗口默认与嵌套动作；不产生肖像的位置单列，未知结构与循环阻塞。

活动保留 `scope:character`，按原相机/原动作建立隐藏别名；两个队列独立检查别名→直接私有相机映射及普通 getter 回退。事件保留原人物位和条件次序，既有正确私有 GUI 调用不撤回。不能按左右名称或普通动作名推断机位。

## 最小诊断与验收

同角色、同动作、同入口比较原路径与已验证私有调用，核对真实尺寸、最终 attachment 和节点。私有调用正常而源头改写后异常，先追别名传播与覆盖优先级；固定诊断镜头只能定位问题，不替代原镜头构图。

`feast_default.2005` 同时检查左位 disgust/very_left 和中位 sick_stomach/center_pointing_left；宴会举杯、牧师、荣誉性格、骑乘分别检查进行中/完成队列。保存实际 CALL、别名和普通人物对照，不以 GUI CAM 参数证明最终镜头。

静态验证包括逆变换恢复原分支、条件顺序与随机候选等价、别名定义/调用闭包、相机参数等价、节点归属。只改路由时保护模型/动画哈希，不重烘。原始源码或生成规则变化才使对应旧证据失效。

实机按用户实际场景验证，未出现目标、队列缓存未更新、遮挡或无有效图不算通过。真实 ActivityWindow 测试不能用带宴会背景的普通事件替代。不使用 computer-use 或新 UI helper；需用户实测时明确范围。

诊断标签正式保留在 绝区零绝区私有相机，以 `[InDebugMode]` 控制根面板；普通模式不显示，Pack 无诊断副本。临时探针、定时器与自动推进不混入交付。
