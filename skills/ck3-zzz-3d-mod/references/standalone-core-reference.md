# 独立前置规则参考的独立边界

独立前置提供共享入口、选模、外观备份/恢复、3D开关、姿势、相机/分流、理发店与兼容。本人网格、动画、Shader、贴图和挂点由Pack提供；身份和玩法由角色包提供。接口历史契约见[拆分共用规范](zzz-core-pack4-workflow.md)，资源算法见[五条核心链](code-reference.md)。

## 后续提取的代码参考

| 算法来源 | 应提取的职责 |
|---|---|
| `selection_cards.py` | 显式角色卡片与可用Pack驱动的显示规则，不内置真实阵营图片 |
| `rui_compat.py` | 复用现有展示选择器，无RUI及两种顺序分别检查，保持RUI死亡/婴儿边界 |
| `props_validation.py` | 原版道具、兜底定义、提供者优先级和调用链检查 |
| `script_parser.py`、`script_sim.py` | 受限脚本结构分析与规则模拟，明确不等于游戏引擎 |
| `formal_transaction.py` | 如需自动安装，抽出通用目标白名单、逐项回读与中断恢复原语 |

本轮提供职责/接口说明，没有复制旧前置生成、安装或恢复代码。`split_build.py`及当前维护器固定本机路径、快照、角色名单与旧收据，不能作为新环境的通用入口。需从其函数提取规则，以调用者现状建立新的目标、来源与候选，禁止复用旧安装记录。

独立模式只改变所选目标外观，角色包联用通过创建后回调；没有对应Pack时安全回退。所有已加载判定依据当前加载内容，不依据技能快照或存档残留模式变量。

未来新增前置适配时，使用者提供自己的当前GUI/脚本输入。共享入口改变需检查普通人物、儿童、死亡、3D关闭及缺席Pack分支；当前包资源生成不能顺带改写其他包。五条核心链的自动测试不证明这些游戏规则或UI表现通过。
