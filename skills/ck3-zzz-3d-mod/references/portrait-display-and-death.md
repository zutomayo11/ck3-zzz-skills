# 展示待机、静态头像与死亡入口

用于默认姿势不一致、小头像不跟随手选、地图头像遗漏和死亡仍播放待机。来源与包边界见[共用规范](zzz-core-pack4-workflow.md)。交付编号是历史快照，实际成品与收据优先。

## 从入口追到片段

分别记录 GUI 控件、实际人物作用域、取图 API、环境、相机、动作类别、画像分支、head/torso 状态及文件。`idle`、`zzz_core_menu_idle`、实体 `idle_entry`、实体 `dead` 是不同层的标识，不能按名称猜测其行为。

动画类别的 `default` 只是回退值，改成 Galgame 不会关闭性格、健康或职务等自动加权分支。当前游戏随附 `_animations.info` 说明首个权重达到100的分支直接命中、全部权重为零才回退；维护时核对当前游戏说明、分支顺序和条件。规则模拟不是引擎执行证据。

理发店按钮设置姿势标志，并非修改所有窗口的全局动画。每个窗口必须请求读取该标志的类别。资源存在、回退字段正确和手选成功，均不能证明无手选时的实际默认姿势。

## 展示优先级与原版动作

交付111的私有展示规则为：手选姿势优先；无手选时，保留特殊状态、身份和职务动作及其相互优先关系；没有适用特殊分支时使用本人 Galgame。每个人当时关闭53个普通自动分支，保留61个特殊分支；数量是快照，不是后续生成器必须匹配的常数。

- “默认站姿”使用本人 Galgame；“原版默认站姿”使用已注册的 CK3 待机状态。保留用户已有选择，不更新时批量清除标志。
- 手选通过现有标志集合使保留的自动分支归零。核对所有可选姿势和女性画像别名，不能只测试两个默认按钮。
- 修改范围是展示类别；事件、活动、内阁和宫廷继续按各自原版选择条件播放 CK3 重定向动作。死亡主面板另有死亡优先入口，不能被活人手选姿势覆盖。
- 活人且满足实际3D接入条件时，`zzz_core_display_animation` 返回私有展示类别；普通人物、3D关闭及该选择器的死亡路径保留 `idle` 回退。不要把展示选择器改成全局强制私有类别。

## 小头像、生活方式与地图标记

| 入口 | 保持的取图方式 | 动作参数与检查 |
|---|---|---|
| 头部、肩部、关系等小头像 | 静态 `GetPortrait` | `Character.Custom('zzz_core_display_animation')`；核对具体控件和继承覆盖 |
| 生活方式窗口 | 原有 `GetAnimatedPortrait` | 同一展示选择规则；不改变原API类型 |
| 地图人物标记 `widget_character_icon` | 静态 `GetPortrait` | 单独接入同一选择器，不能假定共享头像修改自动覆盖它 |
| 左下角 HUD、人物主面板 | 原有展示类别或显式死亡分支 | 和地图标记不是同一个控件 |

交付111同步10处静态头像及生活方式；114补齐地图人物标记。地图修复只把固定 `idle` 改成展示选择器，环境、相机、尺寸、遮罩和交互未改。不能把这次交付描述成地图相机高度修复。

切换姿势后分别观察主面板、HUD、小头像、生活方式与地图标记。静态头像使用引擎既有帧采样；未取得缓存故障证据，不增加刷新定时器、改采样时间或清全局缓存。保持静态API，不因头像不变就改成持续动画。

## 真正死亡与旧菜单兼容

死亡路径必须完整检查 `GUI API/类别 → portrait type → head/torso 状态 → 动画 → next_state`。交付113改正了 `dead` 类别和手选死亡项的状态映射，却遗漏普通主面板固定请求 `zzz_core_menu_idle` 的GUI入口，因此“死亡动画齐全”仍会出现待机。

交付115第一阶段为已故且仍满足模型身份、画像、包可用性和3D开关条件的人物增加互斥入口：普通、绘画与牧民主面板使用现有 `GetAnimatedPortraitEvenIfDead` 请求 `dead`，私有画像映射到本人 `zzz_death_pose`。两个已有圣人入口保留。普通/绘画样式、遮罩与活人/普通人物/3D关闭路径保留。

- 死亡身份选择器 `zzz_core_dead_main` 不读取人物变量；Pack2旧桥接变量不带入死亡条件，以保留的画像身份确认接入。死亡分支直接使用已有 `zzz_camera_character_view_main`，参数不改。
- 旧实体 `dead` 在部分角色中仍是菜单兼容待机；另一部分已对应死亡。不能全局重绑或仅凭其中一个角色的映射解释所有死者。真正死亡路径使用 `zzz_death_pose` 且后续状态闭合。
- 星见雅与叶瞬光分别代表不同旧 `dead` 映射，适合作为隔离对照。检查实际已故人物，有/无旧手选标志、普通/绘画、牧民/圣人以及关闭重开和读档。
- 诊断显示 `DEAD MAIN / EvenIfDead`、`REQUEST: dead` 与相机名，证明的是组件请求，不是引擎最终实体状态。若标签仍是旧请求，先查加载来源与实际控件覆盖。

**115仅完成第一阶段，游戏仍为 `NOT_TESTED`。** 日志已证实死者自动换装读取 `zzz_skin` 会出现不支持变量的作用域错误，该问题尚未修复。后续应采用真正条件分支隔离仅活人可用变量，不能假定同层条件会短路；优先保留已保存的基因/定制结果，无可恢复依据时明确回退，不猜测死前变量或编辑存档补值。

静态死者头像、家谱和事件死者等入口没有因115全部切到 `EvenIfDead`。旧实体兼容与外观问题分别取证，不把第一阶段安装写成死亡全功能验收。
