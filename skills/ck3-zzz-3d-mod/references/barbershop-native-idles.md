# 理发店原生动作、空行与道具显隐

仅在制作当前包动作菜单或排查相关异常时读取。复用工程 `scripts/native_idle_menu.py` 和 `tests/test_native_idle_menu.py`，不重新设计原生分组，也不为文本/UI修复烘焙动画。最新本轮报告和实际成品优先于旧清单；1.4.4基线报告为 `reports/native_idle_menu_1_4_4.json`。

## 游戏原名与真正重复

- 保留原片段名称和编号，例如 `Idle`、`Idle_AFK`、`MainCity_Stand_Idle01`；用户要求按绝区零原名显示，不改成自创的动作类别或重新分组命名。
- `idle_name` 统一已知原名大小写并去掉 `_Loop` 别名。共享 `zzz_native_<规范原名小写>` 每种名称只注册一次，不按每个角色再复制全局菜单。实体状态、动画文件和源证据仍使用原始片段名。
- 不把所有 `01/02/03` 都当别名。莱卡恩的 `MainCity_Stand_Idle` 与 `MainCity_Stand_Idle01` 原数据不同；星见雅的未编号都市待机不能被臆造的01替代。`Idle_01/02`、`Idle_AFK_02` 有本人实际片段时保留。
- 合并“实质相同”动作须有同一角色的源/成品证据，比较时间轴、对齐骨轨道、同步表情及道具显隐；时长或文件大小相同不构成证据。没有证据时保留不同片段，不扩大到全部动画库重新研究。

## 逐角色可见，兼容回退不作额外选项

`available_idle` 只解析真实名称别名；`menu_roles` 决定哪些角色拥有该片段。`matching_idle` 的旧兼容回退可保留给存档或直接调用，但回退到同一片段不能当作多个不同的可见动作。

1.4.3基线为16人、75个原生片段、9个共享名称。共享菜单曾列出144条角色路由，69条是缺片段回退；过滤后本人所有片段保留，不重复显示缺失项。爱丽丝有5个实际片段，不应显示无来源的 `Idle_01/02`、`Idle_AFK_02` 或未编号都市待机。这些数量是历史基线，未来从当前 profiles/manifest 推导，不硬编码进生成器。

可见条件使用已存在的可选阵营 trigger 与准确身份 trait，避免引用未启用包的 ethnicity。四包同内容共享 `gui/window_barbershop.gui`、`common/scripted_guis/zzz_native_idle_menu.txt`、原生动画表及中英本地化；新增包需要共享入口时仅做必要的同步，不重新处理旧角色。

## 空白行的1.4.4修复

1.4.3只把 `visible` 放在 `dropdown_item_properties` 的子按钮，外层 item/container 仍占32像素高度；用户实机截图确认了空行。不是动画丢失或名称本地化缺失。

沿用1.4.4生成器：

- 从已安装游戏 `gui/shared/lists.gui` 的 `dropdown_menu_standard` 复制私有 `zzz_native_pose_dropdown`，不修改全局标准下拉类型。
- 可见条件放在 `item` 的根 `container`，整行隐藏；下拉 `dynamicgridbox` 必须有 `ignoreinvisible = yes`。
- 模糊搜索列表保留按钮过滤，包含 `BarbershopPoseDropDown.GetItemsFiltered` 的 `vbox` 同样设 `ignoreinvisible = yes`。
- 保留原生选择索引、悬停、搜索和滚动绑定，不重命名动作。源布局锚点改变时拒绝生成，检查直接相关控件后再适配，不静默覆盖别的UI变化。

测试必须检查根容器层级和布局忽略隐藏项，并比对实际打包 GUI 等于当前生成器。只统计“过滤表达式出现两次”会漏掉错误层级；隐藏按钮不等于隐藏列表行。1.4.4已通过离线结构/引用测试，更新后的实机界面尚无确认，不能把1.4.3截图算作1.4.4通过。

## 原生武器悬浮、皮肤道具遮挡

原生武器显隐与 CK3 挂接道具分开排查。对于 正式模型包私有 Shader，先从最终已发布网格解码骨架，按本人时钟骨名解析真实索引，再逐外观核对所有 `Clock`、机械屏幕 `ScreenClock` 等读取。Pack1/3 旧索引曾统一偏大2，这是该轮数据的错误特征，**不是可以全体硬减2的修复公式**；迁移路径或裁剪辅助骨后旧硬编码可能失效。

索引报告记录骨名、实际顺序、来源及网格哈希。验证表情、眨眼、显隐是否使用同一正确时钟，特殊形态不能漏查。预览从最终 Shader 中读取实际索引和条件，再结合实际骨架绑定与动画求值；若渲染器直接按正确骨名读取，会绕过 Shader 的错误索引而假通过。旧索引必须能被负例拒绝，并抽取隐藏动作和持武器动作的多个时间点，查看真实输出图。

- 按本人 profile 的 `hides_props` 和源运行时规则区分动作。都市/对话一般隐藏可分离道具，`Idle/Idle_Loop/Idle_AFK` 的持武器表现保留；不能一律隐藏所有原生武器，编号待机也以实际规则为准。
- Pack3 的 `hsos6_animation_profiles.hides_props` 对 `maincity_/galgame_` 忽略大小写。纯显隐修复复用 `hsos6_prop_visibility.py`，不重烘焙三人的动作或改 CK3 道具区间。
- Pack4 爱丽丝泳装冲浪板与柚叶泳装武器使用相应 mesh 的 `UV2.y=2` 显隐标记及私人 shader。`spookshack_prop_visibility.py` 同时规划标记和实际材质路由，不能只写 mesh 标记。
- 成品 `.asset` 的道具槽 `shader_file` 必须真正指向含本人显隐函数的私人入口；`court_scene.shader` 不含该函数时不能继续用于该槽。不要因宫廷选取修复覆盖脸部、眨眼或道具私人入口。
- 星见雅的独立武器材质可能需要整槽私有显隐；从实际源材质与最终 slot 映射确定目标，不能凭全人物通用材质编号处理。隐藏对话/城市/CK3重定向中的原生可分离武器，保留本人持武器待机；不要误隐藏 CK3 剑、书、杯、坐骑或机械身体。已有标记、动画和网格满足条件时，只修外围材质路由/私有 Shader，不重做二进制资源。
- `Lycaon_Weapon` 是机械腿等身体部件，不能用包含 Weapon 的名字宽泛删除。原生道具显隐不改 CK3 props 武器、酒杯、马匹、王座等既有挂点路由；隐藏 head 保留当前 绝区零绝区私有相机 契约的独立动态道具节点，按本人状态同步；不得按旧相机专用裁剪规则删轨道。
- 预览必须由 `preview_geometry.prop_visibility_slots` 读取实际 `.asset` shader，再决定隐藏区域。不得在渲染器中强制隐藏道具并据此宣称成品已修复。

换肤造成挂点错位另查[实际外观标签分流](portrait-assembly-and-skins.md)：手动外观未必等于 `zzz_skin`。私有 Shader 实改须做相关编译；共享 court_scene 实改遵守单 `PDX_MAIN` 和原版编译输出对照。只补菜单且 Shader 哈希未变时引用旧证据，不把它写成新增编译或游戏验收。Pack1/3 031 时钟/武器证据与032装配修复分别记录，不把031整体称为可用版本。

## 最小验证与交付

菜单命名或布局修改，在工程目录运行：

```powershell
python -X utf8 -m unittest discover -s tests -p test_native_idle_menu.py
```

检查新增/受影响角色名称与状态引用、可见片段不重复、下拉与搜索的整行布局、四包/新增包共享文件一致。只有共享规则实改时才检查受影响单包及启用组合，数量从当前包清单推导。道具修复另跑对应显隐测试，检查当前外观的 mesh 标记、shader、帧区间、成品引用与必要预览/哈希。无需全项目测试、旧包宫廷重算或全面动画回读。

Mod 修复按 `settings.json.version` 单轮升一次补丁号，并同步必要元数据；仅技能更新不升 Mod。简短汇报根因、最小改动、实际验证与成品路径；离线通过时明确实机尚未验证。
