# 验证证据与边界

## 仓库自动验证

运行[入口页](code-reference.md)的 unittest 与人工数值示例。测试覆盖转换器局部索引对照、截断/越界、坐标变换后的绑定逆关系、镜像绕序、零缩放、四元数同半球、帧优先通道顺序、静态通道、无效 FPS、重复骨名、父先子后、旋转迁移时保留骨长、绑定朝向、反射拒绝、状态闭包、文本注入、四槽蒙皮、文件来源优先级、路径越界及数值回读失败。

全部数值在测试源码中手写；临时目录只创建人工 `.txt` 文件测试引用来源，不读取生产素材、游戏目录、真实收据或存档。示例只输出摘要，不创建资源文件。

相机技能现有脚本测试继续独立运行：

```powershell
python -B -m unittest discover -s skills/ck3-portrait-camera/tests -p "test_*.py"
```

## 实际目标需要补的检查

1. 源版本与来源：精确网格/骨架/动作引用，以及每个实际输入的哈希。
2. 几何与骨架：原顶点、法线、UV、索引、权重、骨名/骨序/父子与绑定回读；没有重排或拉伸原骨。
3. 动画：全部实际片段的帧数、fps、T/Q/S、表情与显隐时钟一致；导出的 `.anim` 由真实后端读取再比较。
4. 接入：最终目录的实体/状态、材质/Shader/Include、画像组、皮肤、head/torso与缺席Pack回退逐项核对。
5. 游戏：主面板、理发店、事件、活动、内阁、地图、载入、宫廷及目标特殊状态分别实测。

自动数值测试的 PASS 只支持其输入契约和覆盖分支。它不证明真实模型已转换、不证明某个Shader编译或面部效果正确，也不证明游戏中装配、接触或实时刷新正常。代码来源的历史用户反馈不转移到新目标。

## 发布内容检查

新增目录只允许代码、依赖声明和文档；不复制生产 JSON/NPZ、图片、模型、动画、完整Mod、备份或旧安装收据。来源索引仅记录软件文件名与源码哈希。仓库原有相机测试夹具为人工错误样例，不属于游戏生产输入。

提交前核对新增文件清单与类型、全文相对链接、语法、全部相关测试及 manifest 的数量/字节数/SHA256。技能安装清单中的 reference 文件不可遗漏，否则安装后会出现链接和模块缺失。
