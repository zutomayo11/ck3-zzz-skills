# 绝区零 3D 模型制作流程

本页把现有制作规则与五条代码参考链放在同一流程中，供 Codex 和使用者定位输入、处理、输出及职责边界。图示由 Diagram Design 生成，仅含文字和矢量形状，不包含实际模型、贴图、动画、成品、备份或旧安装收据。

五条模块是算法参考，不是完整人物包的一键制作器。先读[代码参考入口](code-reference.md)与[输入契约](code-reference-inputs.md)，再按目标工程调用。当前角色、外观、工具版本和支持组合以使用者实际配置为准，不固定为历史快照。

[下载离线 HTML 浏览版本](../assets/production-workflow/production-workflow.html)，在浏览器中打开可切换详细、浅色与深色视图。GitHub 的 Markdown 展示下面的静态 SVG；点击图片可以查看大图，缺少指定字体的平台会使用系统回退字体。

## 1. 制作总览

![六阶段制作流程，每阶段按输入、处理、输出排列，验证贯穿全过程](../assets/production-workflow/overview.svg)

图中的三行是语义槽位，不是组件所有权。顺序为目标与来源确认、精确提取、模型转换、动作制作、装配接入、验证交付。

| 阶段 | 输入 | 处理 | 输出 |
| --- | --- | --- | --- |
| 目标与来源确认 | 当前角色、外观、版本和来源配置 | 核对路由、特殊骨架、输入路径及生成器作用范围 | 当前包制作清单、输出位置和受保护状态基线 |
| 精确提取 | 明确来源的网格、动作索引及资源引用 | 按精确引用定位，解析骨架、逆绑定及同步 T/Q/S、面部曲线 | 本人几何、绑定和原生动作数据 |
| 模型转换 | 顶点、原索引、UV、骨序、权重及逆绑定 | 统一坐标与单位，核对法线和镜像绕序 | 可见网格、骨架与转换后的绑定 |
| 动作制作 | 本人原生片段、CK3 片段及其源骨架声明 | 原生采样或身体映射，同步眨眼和动态道具 | 身体、隐藏层动作及表情时钟数据 |
| 装配接入 | 实际网格、材质、动作及现行 Pack/Core 契约 | 接入状态、画像组和皮肤，校准场景引用与接触 | 当前 Pack 候选和完整接入声明 |
| 验证交付 | 最终候选、依赖及明确支持的包组合 | 实际回读、引用闭包、组合检查与逐入口游戏验收 | 候选、验证报告及逐入口验收状态 |

只制作新增或实际改动的目标。保护原骨长、父子关系、静置比例、逆绑定、蒙皮和 UV；特殊外观各自核对绑定链。精确提取和原生数据处理见[原生流程](native-pipeline.md)，新增包范围见[新 Pack 生产](new-pack-production.md)。

可见身体与隐藏 head 按实际状态和同一时间轴配对；隐藏层保留独立取景和动态道具节点。小型 head 的预加载与实际挂接遵循[拆分架构契约](zzz-core-pack4-workflow.md)，不能裁成相机专用静态副本。

## 2. 五条核心链与动作分支

![转换提供目标骨架，原生动画与CK3重定向分别生成后汇入装配，经验证形成候选](../assets/production-workflow/chains.svg)

模型转换向两个动作分支提供目标骨序与绑定。本人原生动画保留原动作和同步表情；CK3 身体重定向使用其自己的源骨架声明、类别、阶段链和随机变体。两者可以同时存在，原生片段不必先变成 CK3 动作。验证既在各链内执行，也在最终候选阶段汇总。

| 核心链 | 已提供的算法参考 | 生产工程仍需处理 |
| --- | --- | --- |
| [转换](../scripts/zzz_reference/conversion.py) | 源索引核对、坐标与法线变换、镜像绕序、绑定矩阵换基 | 精确提取、Blender 导入/导出、本人网格和逆绑定回读，以及其他顶点通道保护 |
| [动画](../scripts/zzz_reference/animation.py) | xyzw 四元数、符号连续、同步 T/Q/S、零缩放、静态/动态 PDX 动画树和树解码 | 原生动作解析、实际二进制编码、VAT、逐皮肤眨眼、时钟及身体/隐藏动画配对 |
| [重定向](../scripts/zzz_reference/retarget.py) | 父先子后世界矩阵、绑定朝向修正、旋转迁移、原局部平移和比例保持 | 解剖映射、不同外观骨链、根运动、道具与脚底/王座/骑乘接触校准 |
| [装配](../scripts/zzz_reference/assembly.py) | 显式材质、动画和默认状态的最小 `.asset` 文本及引用关系 | 完整状态树、随机变体、隐藏载体、画像组、外观基因、附件、光环和真实 Shader/Include |
| [验证](../scripts/zzz_reference/validation.py) | 四槽权重、父子索引、数值回读和显式来源优先级的相对引用解析 | 实际输出的 VFS/Shader 闭包、支持组合、定向候选及逐入口游戏实测 |

接入代码和外部 PDX 后端说明见[制作接入流程](code-reference-workflow.md)，边界见[验证范围](code-reference-validation.md)。参考代码只从显式解析数据开始；提取器、对应 ACL 解码、Blender 适配器和实际 PDX 编码由使用者提供，不随技能自动安装或抓取素材。

制作时分别核对以下约束：

- 菜单默认待机使用本人 `Galgame_Idle`；原生烘焙参考姿势另行保留，不因菜单换动作改写图集或重定向参考。见[原生流程](native-pipeline.md)。
- 原生零缩放保持原值，使用局部 T/Q/S 处理，避免对奇异世界矩阵求逆。身体、表情、时钟和隐藏层保持同时间轴。
- 身体重定向按片段的源骨架声明和本人各外观绑定处理；眨眼来源与缺源时的调度分别记录，不冒称完整面部骨骼重定向。见[重定向与眨眼](retarget-and-blink.md)。
- 源武器、CK3 道具、机械身体部件分别判定；脚底接触、骑乘支撑面和相机裁切是不同问题。见[接触与取景](mount-contact-and-framing.md)。
- 头发保持不透明，眼部透明层按本人分层处理；宫廷兼容 Shader 每个 MainCode 仅一个 `PDX_MAIN`。特殊外观基因保持 `mode = add`，原生手选优先。见[装配与皮肤](portrait-assembly-and-skins.md)及[架构契约](zzz-core-pack4-workflow.md)。

## 3. 职责边界

![模型Pack拥有资源，独立3D前置维护共享选择和路由，角色包提供可选身份与玩法接入](../assets/production-workflow/boundaries.svg)

| 组件 | 职责 |
| --- | --- |
| 模型 Pack | 模型、皮肤、材质、Shader、贴图、原生动作、重定向、眨眼、隐藏载体、挂点、道具动作、画像组及光环注册 |
| 独立 3D 前置 | 按实际外观识别模型、直接选模、外观恢复、共享姿势菜单、镜头、显示同步、场景分流、理发店入口、可选 RUI 和缺席 Pack 回退 |
| 角色包 | 身份、特质、人物创建、调频玩法、`zzz_skin` 及可选创建回调 |

独立模型组合不依赖角色玩法，不因选模型添加角色身份特质。与角色包联用时，调频由角色包独占，禁止直接选模，按现行契约恢复外观。分别读取[独立前置参考](standalone-core-reference.md)和[角色玩法参考](../../ck3-zzz-portrait-mod/references/role-code-reference.md)。

共享 GUI、可选 bridge 和最终资源引用须覆盖缺席 Pack 与实际支持组合。候选、安装和恢复仅作用于本轮授权目标；失败只撤销本轮写入，不重跑历史全量入口覆盖当前交付。

## 验证证据与图示维护

数值回读、最终引用闭包、支持组合检查和实际输出图审属于离线证据。游戏按主面板、理发店、事件、活动、内阁、宫廷、地图头像、载入、死亡、骑乘等入口分别验收；未观察入口保持 `NOT_TESTED`，用户通过或失败反馈只覆盖其实际范围。图示本身的检查通过不表示 Mod 已在游戏中通过。

图示配色参考[绝区零官网](https://zzz.mihoyo.com/main)公开 CSS：荧光绿 `#d8fa00`、深灰 `#121212`、浅灰 `#efefef`。正文和图中文字使用微软雅黑等系统回退字体，英文页面标题使用 Impact；不打包官网 Mont-Heavy 或印品鸿蒙体，也不宣称完整字体复刻。

三张 SVG 从同目录的 HTML 中导出，颜色变量绑定在各自 SVG 根节点，均不请求外部字体或图片。内容改变时先同步本文与 HTML。导出器默认只取首个 SVG，须按图分别提供单图 HTML；把页面 `.page` 的颜色变量复制为单图 HTML 的 `:root` 定义，保留图中使用的 CSS，并给 SVG 设置 `width="1280" height="720"`。再用 Diagram Design 的 `export_svg.py --system-fonts` 分别导出三个图，检查独立 SVG、图片嵌入及 Markdown 引用后更新仓库清单，不能把总览重复导出为另外两张图。
