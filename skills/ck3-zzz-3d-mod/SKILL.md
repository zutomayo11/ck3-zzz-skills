# 绝区零 CK3 三维角色制作

## 当前基线与新 Pack 范围

当前制作和维护默认采用 **角色包内置 ZZZ Core／正式模型包** 工作线。先读[共用工作规范](references/zzz-core-pack4-workflow.md)，再按任务加载专项参考。2026-10-10圣人光环交付快照为角色包1.3.0、内置Core来源0.6.2、正式Pack1–5 2.0.5／Pack6 1.0.1；25个私有画像组。以当前 settings、成品、加载顺序和安装收据为准。旧 Test 名称只作历史证据。legacy＋pack2-core-test 是仍需角色包的独立测试组合，不是正式前置。静态、离线和用户实测分开记录，未观察入口保留 `NOT_TESTED`。

- 直接复用模型提取、转换、原生动作、本人 `Galgame_Idle` 菜单默认待机、CK3 重定向、眨眼、道具/武器/骑乘、菜单镜头、宫廷/王座与脚底、DDS 和打包实现。通常只增加当前包的角色、皮肤、素材及配置。
- 只转换、烘焙、导出、校准、验证及打包当前包。旧包模型、动画、材质、眨眼图集、镜头和宫廷脚底基准默认不改、不重算、不重新全面审计。
- 修改旧包须有用户明确要求或当前问题的直接证据。新增角色确需共享入口时，只补必要分支并同步同内容共享文本，说明受影响文件；版本登记同步不等于重建旧资源。
- 构建前一次预检当前包全部角色、`group`/PACK 路由、特殊骨架与皮肤分支、输入路径、命名、输出和生成器识别。先确认入口的实际参数与作用范围；不得臆造 `--packN-only`，也不得因旧入口遍历所有包而默认启动全量重建。
- 新包生产及续接按 [新 Pack 生产与 Token 节约](references/new-pack-production.md) 执行；本任务首次需要时读取，后续复用规则摘要与一份极短状态，不加载全部历史或所有参考页。
- 从成熟 Pack 迁移到新阵营或建立 Test 包时，读取 [Pack 模板迁移与修复经验](references/pack-template-adaptation.md)：复用结构，保留本人资源；检查状态重复序号、动态 T/Q/S、共享画像组和最终 VFS，不把 donor 骨数、槽位或旧安装入口当通用规范。

普通 DDS 沿用已审核的压缩与哈希安装流程，面部动画和辅助数据图不纳入普通贴图压缩。`sources/faction_texture_compression/`、`sources/hsos6_texture_compression/`、`experiments/miyabi_texture_compression/` 中已用于正式构建的候选不能当临时文件清理；细节仅在涉及压缩时读 [体积与压缩](references/storage.md)。

## 原版儿童与特质形变

加载 3D 包后，普通儿童显示成人身体，或驼背、其貌不扬等原版特质失去外观效果时，先读 [原版人物年龄与特质形变](references/vanilla-portrait-morphs.md)。检查私有肖像类型、morph 容器和文件注册排序；保持原版人物定义与 DNA，不按角色 ID 补模型。儿童配套修正和形变排序修正已有用户验收，但不证明全部形变或后代遗传隔离均已解决。

## 圣人光环

圣人／封圣角色缺光环，或新增Pack需要沿用光环时，读[圣人光环装配与维护](references/saint-halo.md)。先查特质、宗教、私有画像组的基因／附件／特质修饰注册与实际头部挂点，再查界面裁剪；现行六包在装配层复用原版光环，不逐界面叠图。新增包只补本包注册，原模型、动作和正常相机保持；现行六包安装入口不可作为新包生成器重跑。

## 宫廷动作与脚底定位

廷臣只播放本人待机、交谈朝向异常或脚部沉地时，先读 [宫廷动作与地面基准](references/court-animation-and-grounding.md)。新增包仅处理新增角色的地面基准、王座和场景引用，不重做旧包。用户选择沿用原版随机场景；不要把内阁职位改为固定动作或站位。区分动作选择、场景锚点与真实脚底：专属动画存在不代表已播放，`ground_joint` 位于零点也不代表鞋底落地。保留不同身高及原比例；莱卡恩的机械腿属于 `Lycaon_Weapon`，不能当普通武器忽略。

## 菜单镜头、道具与游戏版本适配

CK3 更新后先按[当前调用及隐藏层契约](references/zzz-core-pack4-workflow.md)追踪真实入口。事件/活动读[路由检查](references/portrait-routing-and-validation.md)；隐藏层制作读[模板迁移](references/pack-template-adaptation.md)。小型隐藏 head 预加载，保留动态取景和道具节点，完整 T/Q/S 与状态闭包必须成立。旧版本的骨数、去节点或全量补丁入口不用于当前包。

## 独立 Pack、私有镜头与网格渲染

- Pack 独立性不是“删掉私有 camera”一个条件。对照最终发布文件和同一 CK3 版本、加载顺序及 Mod 组合下的日志基线，再判断相机是否为故障原因；同时检查跨包 Shader/贴图引用、共享 GUI/bridge 的缺席阵营回退、动作实体和道具挂点、辅助骨架祖先链及 descriptor/登记。发现跨包引用时先定位实际依赖，不凭单次闪退归因于私有相机。
- 使用 ZZZ Core时核对人物作用域、画像组、回退、隐藏载体和本人动画契约；沿用 `zzz_core_active_identity` 及实际 3D 开关。目录改名不构成路由切换理由。
- 特殊事件保留原版相机、动作与选择条件；活动两队列的接入人物使用私有center，普通人物保留typed `GetCamera`，已有骑乘/战车定向取景例外按实际源码处理。不恢复旧420别名或把getter转字符串。torso零基2/75与head22兼容槽及实际挂接链见共用规范。
- 实际事件、活动、内阁、宫廷和特殊状态使用CK3重定向片段，保留随机变体、阶段链与原版道具。普通展示默认本人Galgame，手选及特殊状态优先；其余独立原生动作按菜单注册。六正式包按现行契约维护，不因文档更新重烘资源。
- 网格渲染先查实际实体、mesh、材质、Shader/include 和贴图引用。隐藏载体需有效三角形和 UV；只给小型 head 设置 `streaming = Never`，不全局预加载。Include 按真实 gfx/FX 根解析，不能仅以文件存在或错误相对目录证明闭包。
- 镜头、路由、Shader 或动作修复不得顺带改可见 mesh、导入骨架、父子关系、蒙皮权重、既有动画二进制或角色包接口。若确需改隐藏辅助体，按实际父节点计算挂接变换；不能假设所有辅助节点直接挂在根节点。星见雅的源比例只在外层载体单次使用 `0.889313653343`；服装和附着辅助体不得再次缩放。
- 对最终发布目录逐一展开每个单包及每个受支持的非空组合的资源引用闭包，并同时查 Mod 与游戏资源目录；检查缺席 Pack 时 bridge/可选接口仍有定义、重复资源名是否意外覆盖，以及共享路径内容是否字节一致。只检查生成器输入或源目录不算发布闭包验证。
- 修改前记录受保护的用户与业务状态（如存档、播放集、Mod 登记和工坊 ID）及本轮文件清单；事务失败时只回滚本轮写入的路径，并保留失败日志、报告和测试产物供诊断，不能用全量恢复覆盖后续状态。
- 视觉验收按入口分别记录主菜单、事件、活动、小头像/特效肖像及原生队列；每项都核对实际角色、路由、slot-camera 和成像。成功启动或某一入口正常不代表其他入口通过；静态检查通过后仍须将未观察的画面、道具/骑乘和闪退列为待测。

## 阵营拆分与头发材质

头发材质必须使用不透明 `portrait_attachment`，导出 alpha 固定为 255；眼睛、眉毛和其它面部透明层不得套用头发规则。各阵营 Pack 独立使用，并保持组合兼容；数量和路由从当前正式包独立配置与现行维护入口读取，不以旧 `build_faction_packs.PACKS` 或 Test 清单代替。Pack 携带本阵营模型、皮肤、换装、动作及必要接入声明，共享同步由内置 ZZZ Core 提供；共享文件同路径须字节一致。保持统一3D开关的中文本地化、可选包默认定义及各阵营 logo；检查当前包的最终 descriptor、封面和登记。交付以本轮短状态与相关报告为准，不为新包反查旧全量报告。

默认中文沟通。先确认用户要改的角色、外观、原生动画或兼容行为；已有明确要求直接执行。此技能提供本机工程经验，不扩大任务范围，也不授权发布或覆盖源素材。

## 定位与流程

1. 正式工程为 `D:/CK3-mod/miyabi_3d_mod_project`，资源工程为 `D:/CK3-mod/zzz_game_asset_probe`。新任务首次读取必要规范、设置、当前包 manifest 与最近短状态；续接先读短状态，不重复完整规范、源码或历史报告。路径失效时先搜索，不凭名称重建另一个项目。
2. 按任务读取 [资源、模型与原生动作](references/native-pipeline.md)、[构建、换装与兼容](references/build-and-compatibility.md)、[CK3 动作重定向与眨眼](references/retarget-and-blink.md) 或 [资源体积优化](references/storage.md)。完整源片段及皮肤数量以当次 manifest 为准，不反复读取旧大对话文件。
3. 在生成器和源配置上做小改动，再生成交付文件；不只手改 `.asset`、shader 或生成脚本输出。编辑前说明文件及计划，保留可回退备份。
4. 常规顺序为 `预检 → 转换/构建 → 针对性验证 → 打包 → 最终摘要`。测试和回读仅覆盖新增或实改模块；菜单文字/布局修改不触发模型导出、动画烘焙或宫廷检查。必要预览读取实际成品引用，不能绕过错误材质模拟“已隐藏”；离线预览不等于游戏实测。
5. 每轮 Mod 功能或修复只递增一次 `settings.json.version`，同步描述文件、登记和说明；功能升次版本、修复升补丁。仅更新技能不递增 Mod。命令与日志默认只给返回码、关键统计和输出路径；简短汇报角色、验证、局限、成品与新特殊处理。

续接复用当前短状态、覆盖清单、生成器和取证工具；用户限定只读一次记录时不再回读聊天或大历史文件。用户已要求本任务体系不使用 computer-use；优先现有脚本、日志与合规批量取证，工具不可用时标明待用户实测，不另建 UI helper 绕过限制。

## 理发店皮肤与模型消失

理发店缺皮肤列表、换肤不生效或人物变剪影时，读[原生皮肤与装配排查](references/portrait-assembly-and-skins.md)。自动外观与手动列表分别注册；特殊外观基因保持 `mode = add`，不能改成仅 regular genes 支持的 `replace`。原生手选优先，“跟随角色包”恢复 `zzz_skin`，不新增控制变量。直接加载网格的预览不能证明游戏装配成功。

## 理发店原生动作与道具

保留绝区零原始动作名称和编号，不重做分类命名。仅合并名称大小写、`_Loop` 别名和有源证据的实质相同动作；角色缺少片段导致的相同回退不算一个新动作。沿用 `native_idle_menu.py` 的逐角色可见规则，以及1.4.4的整行容器过滤和 `ignoreinvisible = yes`，避免空白占位。动作菜单、源武器悬浮、泳装道具遮挡或预览不一致时，只读 [理发店原生动作与道具](references/barbershop-native-idles.md) 的相关节。

## 展示、头像、死亡与接触修复

默认值被自动权重覆盖、小头像/地图标记不跟随姿势或死者仍待机时，读[展示待机与死亡入口](references/portrait-display-and-death.md)。小头像保持静态 `GetPortrait`，地图标记独立核查；115死亡主面板仅完成第一阶段，死后换装变量报错未修。

马/战车缺失、裁切或人物悬空时，读[道具、取景与接触约束](references/mount-contact-and-framing.md)。先查完整预期道具链，再分清取景和真实接触；接触用实际蒙皮支撑面，保持地面附件世界变换，不直接套骨盆差或固定高度。

## 保持的约束

- 旧菜单兼容实体 `dead` 与真正死亡类别分开，按本人实际状态核对；真正死亡入口请求 `dead` 类别后选择 `zzz_death_pose`。资源齐全不证明GUI已调用，见[死亡入口](references/portrait-display-and-death.md#真正死亡与旧菜单兼容)。不全局重绑旧实体或修改存档。

- 新角色菜单镜头覆盖头、身体载体、各服装与frontend状态，复用本人对话姿势校准。保护原人物骨名、父子关系、绑定与蒙皮；确需增加无权重兼容节点时按当前索引映射同步资源并拒绝重复适配，不能拉伸原骨或擅自删骨。独立隐藏辅助体按实际挂接管理，预览不用自动居中代替成品镜头。

- 用户约定（0.16.0 起）：当前及以后新增角色的人物菜单默认待机统一使用本人 `Galgame_Idle` 对话待机和同步原生表情。通过 `portrait_emotions.MENU_IDLE` 与各角色 profile 接入，缺本人片段须明确报缺，不能静默改成都市或 CK3 待机。原生导出的 `DEFAULT/default_clip` 仍是烘焙/校准参考，菜单另记 `menu_idle_clip`；不可因菜单换动作而改写情绪组合、图集顺序、身体参考姿势或重定向片段。见 [原生动作流程](references/native-pipeline.md)。

- 原骨长、静置比例、父子关系、蒙皮权重不为适配 CK3 人体而拉伸。千夏由 `integrate_sunna_retarget.py` 接入；其他角色复用 `retarget_characters.py`、`bake_character_retarget.py`、`integrate_character_retarget.py` 与各阵营集成入口，只处理当前角色。旧星见雅 `experiments/miyabi_ck3_mapping` 仍搁置。
- 原生 T/Q/S 与面部曲线保持同时间轴和缩放。可见资源共享本人 torso 姿势；隐藏 head 同时承载独立相机节点和动态道具节点，两类用途分别验证，不能再按旧相机专用裁剪方案删除道具轨道。
- 原生动作、语义映射、组合适配分别标明。已有星见雅 Happy 是 Galgame_Idle 身体加原 Happy/Blink_Happy 曲线的组合，不冒称原游戏单一片段。
- 新增动作前按[重定向参考](references/retarget-and-blink.md)核对类别→肖像类型→实体状态→动画文件。菜单使用本人原生待机；实际事件/活动保留当前 CK3 动作选择和随机阶段，head 按身体状态同步，不为每个动作新建菜单或事件。
- 眨眼按本人各皮肤分别提取眼睑形态，共用一张图集和动作时钟；CK3 眼睑曲线映射与缺源时的自然眨眼调度分别记录，不冒称完整面部骨骼重定向。死亡、睡眠、静置参考与短过渡不能一律强塞周期眨眼。
- 表情时钟的局部坐标依赖各角色根骨绑定；先用已有原生动画验证“图集行号 → 时钟局部平移”关系，不能把千夏的 X 轴写法复制给维多利亚或星见雅。艾莲校服 `campus__Bip001`、爱芮机械形态 `Bip002` 分别重定向；机械眼屏没有眼睑形态键，当前新增 CK3 动作用私有屏幕压缩近似眨眼，原生屏幕完整序列仍未移植。
- 宫廷悬停按 `pack4_court_016.py` 的实际网格和材质兼容规则接入。每个 Shader MainCode 仅一个 `PDX_MAIN`，函数内部选择着色分支；共享原版输出须实际编译对照。面部、眼睛、眨眼和私有道具程序保持，详见[宫廷规则](references/zzz-core-pack4-workflow.md#宫廷悬停与原版模型回归)。
- 常规情绪和独立原生待机分开；公开待机统一注册 `zzz_native_<原片段小写>`，按肖像类型分派各角色的内部状态，不能为每个角色重复注册全局菜单。星见雅不另设“持刀待机”入口，不手摆武器补偿原始绑定。
- 卡通材质是 CK3 近似，不能宣称迁入 Unity 渲染器。头发保持不透明；眼部透明层不能与头发共用处理。
- 角色包内置 ZZZ Core 管理共享镜头、分流、菜单与同步，模型 Pack 管理骨架、动画、材质和道具；按实际职责定位源文件，不再用“涉及3D只改3D工程”划界。纸片人消隐、音擎和调频仍在角色工程维护；共享 ZZZ Core 源为该工程 core_integration。不能借兼容检查顺带改初始化、身份或皮肤接口。正式决议仅“开启/关闭3D模型”，不带 QA 或分角色控制项。
- 本机原游戏素材仅用于本地工程，不自动上传工坊，不把模型、贴图、存档或提取资源复制进技能目录。
